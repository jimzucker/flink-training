##### 1 — Buys and sells

BUY adds, SELL subtracts — confirmed as designed and now stated explicitly, with `BUY +qty / SELL −qty` on the diagram under the Split box.

On making it **testable while randomized**: the generator draws its buy/sell mix from a **seeded** sequence, so the mix is random in shape but identical on every run. That means expected net position per key is arithmetic derivable from the seed, and tests assert the exact signed quantity — a test that only checks "a number appeared" wouldn't catch an inverted sign. Fixtures cover a key that nets **positive**, one **negative**, and one **zero**.

The property that makes this safe: **side affects values only.** It changes the quantity on a key, never how many keys exist or how often they update — so every rate and key count in the expected-output table holds regardless of the mix.

##### 2 — Price at close

```
marketValue = position quantity at window close
            × last price for that symbol at or before window close
```

Both read as of the same instant, so the figure reconciles against the position topic at that timestamp. An average or VWAP would match nothing observable anywhere in the system — which makes it unexplainable when someone asks where a number came from. Window boxes relabelled **`MV @ close`**.

The join has two inputs and advances at the slower one, so if a partition goes quiet the watermark stalls and the one-minute windows stop firing. **On #1 — you were right and I'll own that.** `prices` is keyed by `symbol`, so each symbol lands on one partition where Kafka preserves order, and a single seeded generator emits in event-time order.
